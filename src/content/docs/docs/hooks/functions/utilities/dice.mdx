### Concepts

<LinkButton href="/docs/protocol-reference/ledger-data/ledger-objects-types/random">Random ledger object</LinkButton>

### Behaviour

<Tabs>
<TabItem label="C">

_(Requires the [RNG amendment](/docs/features/amendments/#rng).)_

* Returns a uniformly distributed random integer in the range `[0, sides)`.
* Uses rejection sampling, so every face is exactly equally likely (no modulo bias).
* The value is derived from the ledger's consensus random seed, mixed with the transaction ID, Hook account, Hook hash, chain position, strong/weak execution, callback flag and the WebAssembly parameter. Two executions never receive the same output.
* Each Hook execution can draw at most 256 times. The limit is shared with [`util_random`](/docs/hooks/functions/utilities/util_random).
* The function is only on the Hook import whitelist once the RNG amendment is enabled, so a Hook that imports it cannot be installed before then.
</TabItem>
</Tabs>

### Definition

<Tabs>
<TabItem label="C">
```c
int64_t dice (
    uint32_t sides
);
```
</TabItem>
</Tabs>

### Example

<Tabs>
<TabItem label="C">
```c
int64_t roll = dice(6);              // 0..5
if (roll < 0)
    rollback(SBUF("RNG unavailable"), roll);

accept(SBUF("rolled"), roll + 1);    // 1..6
```
</TabItem>
</Tabs>

### Notes

* **Draws are never undone.** If the transaction fails with a `tec` code (including `tecHOOK_REJECTED`) after a Hook drew random numbers, the RNG state still advances. A rollback cannot be used to "re-roll".
* **Open ledger is only a preview.** While a transaction is applied to the open ledger, draws may use the previous ledger's seed. The authoritative result is decided when the ledger closes, so a Hook's outcome in the open ledger may differ from its validated outcome.
* **Auditability.** The validated metadata of a transaction whose Hooks drew random numbers contains a `RandomData` field. It holds the RNG state seen by the transaction's first draw, and every value its Hooks received is derived from it.
